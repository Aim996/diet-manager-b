## 终审安全修复与 TDD 证据

终审复核确认三个 Important 和一个测试强度 Minor 均真实存在：

1. 普通候选条目没有消费真实进食 occurrence，`桌上有一个苹果，我吃了一个鸡蛋` 可错误记录苹果；同一个 `我吃了一个鸡蛋` occurrence 还能被两个候选鸡蛋重复使用。
2. 非事件分类漏掉 `我明早吃一个鸡蛋`、`我尚未吃一个鸡蛋`、`我没来得及吃一个鸡蛋`，三者都可能提交。
3. 自定义原型数组通过形状检查后，克隆器会调用其继承的 `map`，从而执行调用方控制的 getter/function。
4. OpenClaw nested public v1 schema 测试使用 `toMatchObject`，无法阻止未来静默增加字段。

生产修改前，validator、Application 和注册工具三层回归共同得到有效 RED：3 个测试文件中 18 项失败、69 项通过；所有新失败都返回了可写入候选或真实提交，而期望是专用拒绝/忽略与 SQLite 零写入。TypeBox 运行时边界的精确 schema 测试另以 1 项失败、17 项跳过得到 RED，差异逐项显示缺少字符串、数组和正数边界。

最小修复包括：

- 以 `mealAuthority.proposed_items` 为优先 occurrence 权威，并为 parser 因省略主语/普通修饰词而未选中的真实 ingestion object span，以及 `扒了`/`啃了` 的已完成对象区间，补充只含源码位置的语义 occurrence；候选 evidence 必须覆盖 occurrence，每个 occurrence 只能消费一次。该设计保留 `中午扒了两碗米饭`、`早上顺手吃了一个鸡蛋` 和 `一个煮鸡蛋`，同时拒绝仅“存在”的苹果与重复鸡蛋。
- 扩充语义非事件规则，覆盖明早/明晚及近未来锚点、尚未/仍未/还没和没来得及；原有 `今晚吃了`、先不想后明确吃了的完成事件回归保持通过。
- 数组只接受 `Array.prototype`，逐索引读取数据 descriptor 到新数组；不调用输入数组的 `map` 或其他继承方法。validator、Application 和注册工具均断言 hostile getter 调用次数为 0，Application/OpenClaw 同时断言 SQLite 增量为 0。
- OpenClaw schema 改为 exact equality，并准确镜像 runtime 的 source/evidence/name/unit/items/spans 边界与 exact amount 正数边界；JSON number 本身不表示 `NaN`/`Infinity`，其余有限数检查继续由 runtime fail closed。
