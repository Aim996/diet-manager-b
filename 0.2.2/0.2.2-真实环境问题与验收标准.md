# 饮食管家 0.2.2：真实环境问题与验收标准

- 测试日期：2026-08-20
- 测试对象：五个独立 Docker OpenClaw Agent 环境
- 测试版本：饮食管家 0.2.1 候选包
- 测试方式：通过五个真实 Web UI 并行对话；相同能力类型使用不同人物、食物、数量、时间和口语；同时核对回复、工具结果和 SQLite

## 一、测试结论

安装和底层写库链路可用，但自然语言入口没有充分利用 Agent 大模型的理解结果。系统对少数规范句式表现正常，对普通人的时间词、副词、动词、量词和上下文补充仍然过于僵硬。

一句话结论：**不是账本不会写，而是技能经常把 Agent 已经听懂的话再次判错。**

## 二、通过的能力

### 1. 五环境安装与运行

- 五个容器均成功安装 0.2.1 候选包；
- 重启后五个 Gateway 均恢复健康；
- 插件在五个环境中均启用并可调用；
- Web UI 使用对应 Gateway Token 均连接成功。

### 2. 明确他人保持零写入

五种不同表达分别涉及同事、母亲、孩子、第三人称和室友。数据库新增事件全部为零。

其中两路调用工具并返回 `non_self_subject`，三路由 Agent 直接当作普通对话而没有调用工具。安全结果正确，但路由行为不完全一致。

### 3. 规范的本人餐食可以写入

“我吃了个苹果”“我吃了两碗米饭”“我吃了两片面包”“我吃了一个鸡蛋”“我吃了一个香蕉”等较规范表达可以写入，证明餐食领域内核和数据库链路正常。

### 4. 一条口语撤销成功

“刚才苹果那条先取消”在同一会话只有一个有效餐食时成功写入纠正事件，原餐食事实保持追加式审计。

### 5. 部分自然入库成功

“今天带回来两瓶牛奶，先放进库存”和“今天带回来一包燕麦，先放进库存”能够提交。牛奶的两瓶外包装证据正确保留。

## 三、已确认的问题

## P0-1：默认本人仍被错误拒绝

五个环境同时测试五种不同的省略主语自然餐食，结果全部未写入：

| 环境 | 用户自然表达 | 工具结果 |
|---|---|---|
| 01 | 刚才吃了个橘子，酸得我直皱眉 | `amount_ambiguous` |
| 02 | 中午扒了两碗米饭，这会儿还撑着 | `non_self_subject` |
| 03 | 早上顺手吃了一个鸡蛋，差点忘了说 | `non_self_subject` |
| 04 | 下午嚼了三颗草莓，没怎么顶饿 | `non_self_subject` |
| 05 | 夜里啃了两块饼干，嘴馋没忍住 | `non_self_subject` |

这些表达没有提到其他人。在私人饮食 Agent 中，正常产品预期应是默认本人，而不是要求用户不断补“我”。

另一个明确问题是“我出门前吃了两片面包和一个煮鸡蛋”仍被判为 `non_self_subject`。这说明即使出现“我”，只要“我”和“吃”之间加入普通时间表达，规则仍可能失败。

## P0-2：饮水入口大面积冲突

五种不同饮水表达全部未写入：

| 环境 | 表达 | 真实工具结果 |
|---|---|---|
| 01 | 刚才喝了三百毫升水，嗓子舒服多了 | `ACTION_CONFLICT` |
| 02 | 这会儿喝了半瓶水，还是有点渴 | `ACTION_CONFLICT` |
| 03 | 我刚喝了一杯水 | `needs_clarification/amount_ambiguous` |
| 04 | 顺手灌了两口水，缓过来了 | `ACTION_CONFLICT` |
| 05 | 刚运动完，我喝了五百毫升水 | `ACTION_CONFLICT` |

“一杯”需要补充毫升数是合理澄清；“半瓶”在不知道瓶子容量时也应该澄清。但明确的三百毫升和五百毫升不应发生动作冲突。

本轮数据库核对确认五个环境的新增饮水事件均为零。

## P0-3：撤销只覆盖少数固定说法

五个环境先分别建立唯一有效餐食，再用不同口语撤销：

| 撤销表达 | 结果 |
|---|---|
| 刚才苹果那条先取消 | 成功，写入纠正事件 |
| 前面米饭那顿算了，帮我去掉 | `ACTION_CONFLICT` |
| 早上的面包不记了 | `ACTION_CONFLICT` |
| 刚才鸡蛋那次别算了 | `ACTION_CONFLICT` |
| 夜里那个香蕉撤掉吧 | `ACTION_CONFLICT` |

数据库中只有第一个环境出现新增纠正事件，其余四个餐食仍有效。当前实现不是“理解撤销意图”，而是命中了少数受支持句式。

自然恢复也失败：“刚才撤掉的苹果其实还是算上吧”返回冲突，苹果保持撤销状态。

## P0-4：澄清无法承接上一轮

已复现两类多轮失败：

1. 用户说“早上随手吃了根香蕉”，系统追问是否本人；用户回答“是我自己吃的，就一根香蕉”，系统仍要求重新说明食物。
2. 用户说“出门前吃了两片面包和一个鸡蛋”，系统追问是否本人；用户回答“是我自己吃的，面包两片、鸡蛋一个”，系统仍无法承接原句。

根因表现是每一轮都把用户消息当成全新孤立句子，没有保存待补充候选。

## P0-5：库存路由和商品投影不稳定

五种自然入库表达的结果：

| 表达 | 结果 |
|---|---|
| 买菜回来顺手带了一袋苹果，先搁厨房了 | Agent 未调用工具 |
| 今天带回来两瓶牛奶，先放进库存 | 成功 |
| 刚拎回来三盒鸡蛋，先塞冰箱里了 | Agent 未调用工具 |
| 下班带了四罐酸奶回来，放冰箱了 | `ACTION_CONFLICT` |
| 今天带回来一包燕麦，先放进库存 | 成功，但投影名错误 |

另一次“今天带回来一盒酸奶，先放进库存”成功写入，但产品投影把酸奶显示成 `product`。查询“冰箱里现在有啥”时只能看到未命名通用商品，无法显示酸奶。

燕麦也保留了原始名，但规范化产品名同样落为 `product`。这会让库存查询、选择和后续扣减失去可读身份。

## P0-6：回复与工具真相不一致

已观察到以下不一致：

- 工具返回 `ACTION_CONFLICT`，回复却解释为用户没有说明容量；
- 工具未调用时，Agent 有时把用户内容当作已知事实闲聊，但没有明确说明未入库；
- 工具失败后追加身份初始化、工作区说明、内部维护建议或无关营养建议；
- 酸奶工具显示提交成功，但后续库存查询只能看到 `product`。

回复不能成为第二套事实来源。最终说法必须由工具状态和数据库结果约束。

## 四、集成与部署观察

以下问题在本轮出现，但需要与核心语义缺陷分开处理：

1. 命令行 Agent 启动时多次提示插件的 `skills` 路径不存在。工具仍可调用，但技能指令可能没有按候选包预期安装，应列为打包门禁。
2. OpenClaw 提示非内置插件被自动发现，而 `plugins.allow` 为空。测试环境可运行，正式安装应显式信任插件 ID。
3. 容器内命令行连接 Gateway 时发生 WebSocket 异常并回退到 embedded Agent；Web UI 直接连接五个 Gateway 正常。该问题属于宿主/容器连接配置，不应误判为饮食数据库故障。
4. 新会话中 Agent 多次插入“给我起名字”“完成初始化”等内容。这属于宿主工作区体验问题，但会干扰饮食操作回复，应在集成验收中单独记录。

## 五、0.2.2 验收标准

## A. 默认本人

- 没有明确他人的自然餐食和饮水默认本人。
- “中午扒了两碗米饭”“早上顺手吃了鸡蛋”“刚运动完，我喝了五百毫升水”等本轮原话必须通过。
- 明确他人反例仍保持五环境零写入。

## B. 数量与饮水

- 明确毫升数直接提交。
- 杯、瓶、口等容量未知时返回具体澄清问题，零写入，不得返回动作冲突。
- “个、根、颗、片、块、碗”等常见量词可以保留明确数量；无法换算营养重量时允许数量明确、营养未知。

## C. 撤销与恢复

- 同一会话只有一个有效餐食时，苹果、米饭、面包、鸡蛋和香蕉的自然撤销都成功。
- 同一会话存在多个有效候选时必须澄清，零纠正写入。
- 恢复只针对明确的已撤销记录，不把第二次撤销误当恢复。

## D. 多轮澄清

- 用户回答“是我吃的”后，系统能补齐上一轮主体并提交原候选。
- 用户只补充容量或时间时，不要求重复完整句子。
- pending 候选过期、跨会话或多候选时安全拒绝。

## E. 库存

- 五个环境使用五种不同商品和自然说法，均能正确路由或给出准确澄清。
- 牛奶、鸡蛋、苹果、酸奶和燕麦在库存视图中保持可读商品名。
- 外包装数量正确；未知内含量保持未知，不得虚构。
- 地点表达“冰箱、厨房、冷冻”等进入正确位置投影。

## F. 三方一致性

每个真实 UI 用例必须同时断言：

1. Agent 最终回复；
2. 工具 action、status 和 reason/error code；
3. SQLite 的事件、餐食明细、库存批次或纠正事件增量。

任意一方不一致即失败。前置 setup 失败时，后续场景标记为被阻断，不得计为通过。

## G. 安装门禁

- 候选包包含插件实际声明的 Skill 目录与文件；
- 五个环境插件版本、启用状态和配置根一致；
- 重启后 Gateway 健康、工具可发现、数据不丢失；
- 正式安装显式配置可信插件列表，不依赖自动发现警告。

## 六、建议修复顺序

1. 建立结构化语义候选契约和真实原话红灯测试。
2. 修复默认本人和明确他人的新安全边界。
3. 修复明确毫升饮水与容量澄清。
4. 泛化唯一候选撤销，同时保留多候选保护。
5. 增加 pending candidate，多轮承接澄清。
6. 修复库存路由、商品规范化和位置投影。
7. 加入回复、工具和数据库三方一致性门禁。
8. 修正候选包 Skill 路径和可信插件配置，再做五环境复验。
