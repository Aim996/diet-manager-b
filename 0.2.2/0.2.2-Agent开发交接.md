## 5. 真实 UI 测试的权威结论

详细原话和表格见 `0.2.2-真实环境问题与验收标准.md`。Agent 开发时至少要记住以下结论：

1. **安装链路正常**：五个插件均可发现、可调用、可写库。
2. **明确他人安全边界正常**：五种不同他人表达全部零写入。
3. **默认本人失败**：五种不同自然餐食表达全部未写入。
4. **饮水失败**：五种表达全部未写入；明确毫升数仍可能 `ACTION_CONFLICT`。
5. **撤销过度依赖固定句式**：五种口语中只有苹果固定表达成功。
6. **多轮澄清失败**：“是我自己吃的”不能补齐上一轮候选。
7. **库存不稳定**：部分说法不调用工具，部分冲突；酸奶、燕麦会投影成 `product`。
8. **回复不总是真实**：Agent 有时把工具冲突解释成数量不清，或在失败后追加无关内容。
9. **打包有警告**：运行时提示插件 Skill 路径不存在，且测试环境依赖非内置插件自动发现。

这些结论来自真实 Web UI、工具详情和 SQLite 三方核对，不得用单元测试通过来否定。

## 7. 第一批开发范围

第一批只解决“Agent 已理解，技能怎样安全接收和验证”，不要一次把饮水、撤销、库存和多轮状态全部重写。

### 7.1 第一批应新增的边界

建议新增两个专责模块，实际文件名可按现有项目风格调整：

```text
src/semantic/candidate.ts
src/semantic/validate-candidate.ts
```

职责：

- `candidate.ts`：定义 `SemanticCandidate` 及餐食、主体、数量、时间的证据结构；
- `validate-candidate.ts`：验证结构化候选与原话、安全边界和动作一致性；不得访问数据库。

现有模块的预期改动点：

```text
src/contracts.ts
src/openclaw/plugin.ts
src/application/core-runtime.ts
src/parser/subject.ts（逐步降级为兼容/验证用途）
```

不要删除现有 `ACTION_CONFLICT` 守卫。应把“结构化候选与动作不一致”和“旧 parser 路由不一致”区分为更准确、可诊断的结果。

### 7.2 第一批红灯

先写测试证明以下行为当前失败：

1. Agent 提交 `record_meal` 的结构化候选，原话为“中午扒了两碗米饭，这会儿还撑着”，主体应按私人 Agent 默认本人。
2. “早上顺手吃了一个鸡蛋”默认本人。
3. “我出门前吃了两片面包和一个煮鸡蛋”明确本人。
4. 结构化候选声称本人，但原话明确是“我同事吃了”时必须拒绝并零写入。
5. 候选缺少数量时返回具体澄清，不得造数。
6. 旧 `source_text` 调用方仍按兼容路径工作。

第一批完成标准是：结构化餐食候选可安全提交，明确他人仍零写入，旧调用不回归。饮水、撤销和库存留到后续独立批次。

## 8. 后续批次顺序

必须按以下顺序推进，每批独立红灯、实现、验证和提交：

1. 结构化候选契约 + 默认本人餐食；
2. 饮水：明确毫升提交，杯/瓶/口容量澄清；
3. 撤销：不同食物口语泛化，唯一候选自动绑定，多候选澄清；
4. pending candidate：承接“是我自己吃的”等补充；
5. 库存：自然路由、商品身份、包装数量和位置投影；
6. 回复、工具和数据库三方一致性；
7. 候选包 Skill 目录、可信插件配置和宿主连接收尾。

禁止把七个批次混成一个超大提交。

## 9. 测试与验证规则

### 9.1 开发方法

- 使用测试驱动开发：先看到预期红灯，再写最小实现，再看到绿灯。
- Bug 未定位根因前，不扩大正则或删除安全守卫。
- 每个新放宽规则必须有明确他人、否定、计划、跨会话、多候选或超界反例。
- 不以 Agent 回复文本代替数据库证据。

### 9.2 本地命令

### 9.3 每批验证门

1. 聚焦红灯已复现；
2. 最小实现后聚焦测试全绿；
3. 相邻 parser/application 测试全绿；
4. TypeScript 构建通过；
5. 完整 portable 回归只跑一次且全绿；
6. `git diff --check` 通过；
7. 只提交当前批次文件。

任何一步失败，不得打包或部署。

## 10. 五环境复测规则

本地完成一个有用户价值的批次后，统一打包并只部署一次。不要恢复“发现一个问题就部署五台，再发现一个问题又重来”的循环。

### 必须这样测

- 五个环境测同一种能力；
- 五个环境使用不同人物、食物、数量、时间和自然说法；
- 模拟第一次接触技能的陌生用户；
- 使用正常口语，不要求用户说“执行记录”“写入库存”等指令词；
- 每条同时核对 Agent 回复、工具结果和 SQLite；
- 必要 setup 失败时，后续场景标记为被阻断，不能计通过；
- 定时观察五个 Agent 是否仍在生成、已结束或需要处理，不得只等最终文本。

### 不得这样测

- 五台复制完全相同的问题和数据；
- 只调用 parser 或工具，绕开真实 Agent；
- 只看回复，不查数据库；
- 为了得到绿灯把自然说法改回规范命令句；
- 在正式环境测试未完成版本。
