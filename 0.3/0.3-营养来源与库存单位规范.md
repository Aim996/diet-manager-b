# 饮食管家 0.3 营养来源与库存单位规范

> 状态：已确认  
> 用途：规定商品营养表、本地与联网营养来源、搜索留档，以及包装数量和内容量的库存换算  
> 关联材料：[0.3-设计决策记录.md](./0.3-设计决策记录.md) · [0.3-开发目标与验收场景.md](./0.3-开发目标与验收场景.md)

## 1. 营养查询与库存匹配相互独立

- 饮食事实成功后，无论是否匹配库存，都必须尝试取得营养数据。
- 没有匹配库存时，库存回执简洁显示“未匹配有效库存”，但不能因此停止营养查询。
- 有库存但商品没有营养表时，系统不能直接把营养标记为永久未知；必须继续执行营养来源匹配、联网检索或估算流程。
- 营养仍无法取得时，饮食事实保持有效，进度按照未知规则展示，不能把未知当成 0。

## 2. 营养来源优先级

同一食物存在多个候选来源时，默认优先级如下：

1. **用户本地商品营养表**：用户上传、拍照识别或手工确认的包装营养表，绑定到具体商品或规格版本。
2. **Skill 本地通用营养库**：鸡蛋、苹果、米饭等通用食物的标准营养数据。
3. **联网检索来源**：前两级均未命中时，通过可追溯互联网来源搜索商品或食物营养。
4. **估算数据**：仍无精确来源时，依据同类食物、份量或配方形成明确标注的估算。

用户在本轮明确提供并确认的营养数据，按用户本地商品营养表处理，优先于其他来源。

## 3. 用户本地商品营养表

用户库存中的加工食品可以绑定私有营养资料。例如用户有一款“小象饼干”，上传其包装营养表后，系统保存：

- 用户范围和商品稳定身份。
- 商品名称、品牌、规格、口味或配方版本。
- 营养表的每份基准，例如每 100g、每包或每片。
- 热量、蛋白、脂肪、碳水、纤维等已知值。
- 用户原始输入、图片或识别证据的引用。
- 用户确认状态、创建时间和版本。

后续入库、消费或饮食记录高可信匹配到该商品时，优先使用这份营养表进行换算和回执。商品规格或配方变化时创建新版本，不静默覆盖旧记录使用过的营养快照。

## 4. 联网检索与营养库补充

本地商品营养表和 Skill 通用营养库都未命中时，允许联网检索。每次被采用的检索结果必须保存：

- 原始查询词和规范化食物或商品名称。
- 来源名称和可追溯地址。
- 检索时间、份量基准和单位。
- 匹配范围：具体商品、某一规格或通用食物。
- 匹配置信度及是否属于估算。
- 实际采用的营养值和来源版本。

采用结果写入带来源的营养缓存，便于后续复用。联网结果不能伪装成用户包装标签；低置信或仅为同类食物的数据必须标为估算。来源失效、产品改版或超过复核期限时允许重新查询，但历史饮食继续保留当时冻结的营养快照。

## 5. 估算优先保证使用流畅

例如用户说“吃了 250 克杂粮粥”，本地和通用营养库没有可靠精确条目时：

1. 记录 250 克杂粮粥的饮食事实。
2. 尝试联网查询通用杂粮粥或相近配方。
3. 无法获得精确数据时，使用合理的同类食物估算或估算范围。
4. 回执明确显示“营养来源：估算数据”，不能表达成包装实测值。
5. 保存估算依据和来源，后续用户补充真实配方或标签时建立新营养版本并重算进度。

## 6. 饮品属于摄入项目

- 牛奶、豆浆、果汁、含糖饮料等饮品属于可摄入项目，必须参与热量和营养计算。
- 白水也属于摄入事实，虽然通常没有热量，但参与饮水进度。
- 含热量饮品同时贡献营养和已知水分；白水与饮品水分不得重复计算。
- Agent 不得因为输入类型是“饮品”就将其判断为非食物、忽略或转为普通文本。
- 后端可以在内部区分食物、含热量饮品和白水，但三类都属于消费记录体系。

## 7. 库存双单位模型

库存必须同时区分：

1. **包装数量单位**：盒、袋、瓶、罐、包、片、个等用户购买和查看库存时常用的单位。
2. **内容基准单位**：ml、g、个、片等实际可扣减和换算的基础单位。

例如“两盒纯牛奶，每盒 250ml”至少保存：

```text
包装数量：2
包装单位：盒
单包装内容量：250
内容单位：ml
入库总量：500ml
剩余基础量：500ml
```

## 8. 入库与出库换算

- 用户按包装消费“一盒牛奶”时，使用已保存规格确定扣减 250ml。
- 用户按容量消费“喝了 100ml 牛奶”时，直接扣减 100ml，并保留包装规格用于友好展示。
- 扣减 100ml 后，可显示“剩余 400ml（约 1 盒 + 150ml）”；权威余额是基础量 400ml。
- 没有明确包装规格时，不能把盒、袋或瓶猜成某个容量。
- 质量和体积之间不能直接换算；只有存在经过确认的密度或商品规格时才能转换 `g` 与 `ml`。
- 鸡蛋等自然计数商品可以使用“个”作为包装与基础单位，不强制猜测重量。
- 多批次时先选择实际扣减批次，再在该批次内执行单位换算和先进先出。

## 9. 精简库存回执

普通饮食回执只保留用户需要立即知道的结果：

```text
已记录晚饭：全麦面包 2 片、苹果 1 个。面包库存仅 1 片，已扣减，当前库存 0；苹果未匹配有效库存。
```

随后按照 [0.3-进度回执规范.md](./0.3-进度回执规范.md) 强制输出一个完整六项进度块。详细批次、未覆盖数量、换算过程和营养来源保存在结构化结果中，只有用户查询详情或需要消歧时再展开。

## 10. 数据与回执验收

- 相同商品后续消费优先复用用户已经确认的本地营养表。
- 本地未命中时查询 Skill 通用营养库，再联网搜索，最后明确估算。
- 被采用的联网结果和估算依据均可审计并可复用。
- 饮品不会因类型判断被漏记营养。
- 入库可以按盒，出库可以按盒或 ml，结果落到同一基础余额且可复算。
- 未知营养不转换为 0，未匹配库存不阻止饮食和营养处理。
- 普通业务回执保持简短，完整六项进度块仍然强制显示。
