# 回执与进度

## 何时读取

当需要解释工具结果、处理澄清/失败、展示简洁正文或六项进度时读取。

## 以结构化结果为唯一事实

先检查 `committed`，再检查 `status`。如果适配器或 CLI 返回 `render_model.text`，逐字作为用户可见业务回执；不要从 `receipt`、库存或营养明细重新拼数字。结构化 `details` 用于审计和后续查询，不授权 Agent 补充结果中没有的事实。

| 状态 | 必须做 | 禁止做 |
|---|---|---|
| `committed=true/status=committed` | 展示后端成功正文 | 再查一次确认、补数字或追加建议 |
| `committed=true/status=committed_with_issues` | 同时说明已提交事实和返回的问题 | 把联动问题说成整次失败，或重新提交 |
| `committed=false/status=needs_clarification` | 第一处明确“尚未记录”，只问返回的最短问题 | 提前写入、要求整句重说或循环猜字段 |
| `committed=false/status=ignored` | 查询结果只读展示；非事件说明未记录 | 把查询说成写入，或对非事件更新进度 |
| `committed=false/status=failed` | 明确未记录，可报告 `error_code` | 重试、切换入口、写记忆或声称成功 |
| 缺字段、未知状态或 `committed/status` 矛盾 | 视为未确认成功 | 猜测真实状态 |

## 冻结进度

终态成功的饮食、含营养饮品或白水回执末尾必须有且只有一个后端冻结的进度块；更正、撤销或恢复影响多个日期时，按后端给出的日期顺序展示。Agent、Skill、CLI 和 OpenClaw 都不得计算或改变百分比、10 格条、累计、目标、本轮增量、未知状态或饮水下界。

六项固定顺序是热量、蛋白、脂肪、碳水、纤维、饮水；第二项只能显示“蛋白”。未知不能当 0，已知下界使用后端返回的 `≥`。正式目标未配置时展示后端的“目标未配置”状态，不能拿推荐值补齐。

必要效果或最终器仍为 `pending/retryable_failed` 时不得出现成功标题或正式进度。进度块之后不追加表扬、警告、健康建议、剩余额度或下一餐推荐。

## 查询与无工具降级

查询结果可以是 `committed=false/status=ignored/reason_code=read_only_result`；这表示只读成功，不是业务失败，也不是写入。只呈现返回数据。

没有可调用适配器或 CLI 时明确说本次无法持久化/未保存。可以把 v2 待提交内容交给用户，但不能制造记录 ID、库存余额、营养来源或进度。
