# v0.1 变更说明

## 已开发并验证

- 餐食事实记录：保存用户原话、时间证据、本人主体和食物条目；营养证据缺失时保留事实并标记 unknown，不编造热量或营养值。
- 饮水事实记录：明确毫升白水形成独立事实并进入每日饮水汇总；营养饮品不冒充白水。
- 查询：支持餐食历史、每日汇总和库存只读结果，查询本身不写入业务数据。
- 明确包装采购：冻结语法下的箱、盒、容量关系可写入库存并支持查询。
- 零写边界：未来计划、否定句、非本人事实、混合饮品和数量不明确场景保持不写入。
- 重放和事实身份：同一请求复用既有结果，不重复增加事实。
- OpenClaw Skill：插件清单已经注册 `skills/diet-manager-b/SKILL.md`，限制单次业务调用、禁止工具循环和未授权提醒兜底。
- 回复真实性：`committed=false` 时必须先说明未记录，不得说成已保存或已更新。
- 最新集中修复：支持常见食物克重；保留“米饭 + 鸡胸肉”等多食物条目；支持“晚饭”“刚喝”等本人省略主语；公开 `needs_clarification.question`，不再只返回模糊冲突码。

## 已开发但仍需 OpenClaw 实例复测

- 最新多食物、克重、晚饭前缀和具体澄清修复已经通过 217 条受影响测试及类型检查，并只构建一次。
- 该构建尚未更新并复测全部 02–07 实例，因此不能把全部自然语言表现写成生产验证完成。

## 尚未完成

- `undo_record` 仍返回未实现；尚未追加撤销事实。
- 日常口语的公开库存位置纠正仍不完整。
- “2盒牛奶，每盒250ml”等单层包装采购尚未形成稳定库存写入模型。
- 多商品采购的完整规格澄清和原子提交仍需继续开发。
- 部分 OpenClaw 回复仍可能出现起名、提醒、能力推销或建议换说法重试；需继续区分插件说明与工作区上层提示的优先级。
- v0.1 不是 0.4 全部增强功能的完成声明；0.3/0.4 的原始基础与后续计划保存在 `docs/root`。

## 已知环境限制

- 当前 Windows 测试环境缺少可用的 PowerShell ACL 模块时，涉及私钥 ACL 的完整应用测试可能返回 `CORE_RUNTIME_SECRET_INVALID`；这属于环境门，不等同于餐食解析回归。
- 安装、Gateway 重启和正式数据访问不包含在本版本目录生成步骤中。
