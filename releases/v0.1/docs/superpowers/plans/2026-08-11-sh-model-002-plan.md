# SH-MODEL-002 Nutrition and Progress Model Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Freeze a shared JSON Schema v1 for nutrition profiles/snapshots, goal versions, daily progress, cross-day progress results, and the single four-value `CoverageStatus`.

**Architecture:** One route-neutral JSON Schema references the frozen decimal-string definition from SH-MODEL-001 by absolute `$id`. A fixed full-object fixture corpus drives a dependency-free Windows PowerShell 5.1 validator that separately enforces JSON shape and semantic invariants such as known/missing consistency, six-metric coherence, date ordering, and single-day alias equality.

**Tech Stack:** JSON Schema 2020-12, JSON, Markdown, Windows PowerShell 5.1, SHA-256.

## Global Constraints

- Route B remains the only future writer; this task adds no A/C implementation and no route score.
- Create no SQLite table, migration, repository, business record, runtime adapter, renderer, OpenClaw/MCP handler, or installable Skill.
- Use canonical decimal strings for persisted quantities; JSON numbers are invalid and unknown is never numeric zero.
- The only `CoverageStatus` values are `complete | partial | unknown | not_applicable`; `estimated` belongs to field evidence.
- FactCommit/finalization failure may create a separate redacted technical log but creates zero dietary business objects.
- Do not read, hash, track, edit, or execute the five protected lease files.
- Follow TDD: the validator must fail for missing deliverables before schema/fixture implementation begins.

### Task 2: Implement the schema and fixed fixture corpus

**Files:**
- Create: `shared/schemas/nutrition-progress.schema.json`
- Create: `shared/tests/fixtures/nutrition-progress-cases.json`

**Interfaces:**

- Produces: schema v1 with exactly ten definitions and a fixture set whose exact bytes are pinned by the validator.

- [x] **Step 1: Add schema identity and shared definitions**

Create a draft 2020-12 schema with exact `$id`, `x-schema-version: 1.0.0`, `unevaluatedProperties: false`, and definitions:

```json
"CoverageStatus": { "enum": ["complete", "partial", "unknown", "not_applicable"] }
```

`NutrientValues` has exactly ten nullable decimal-string properties; `MetricValues` has exactly the six nullable progress properties; `MetricCoverage` has the same six keys and references `CoverageStatus`.

- [x] **Step 2: Add NutritionProfile and NutritionSnapshot**

`NutritionProfile` is exact-shape, immutable/versioned, and carries source/basis/serving/nutrient/evidence/coverage/supersession fields. `NutritionSnapshot` is exact-shape and carries meal/item/profile version, source/basis/consumed amount, nutrient values, formula/rounding, estimated/known/missing sets, coverage, and creation time.

The schema rejects generic `status`, JSON-number quantities, unsupported coverage values, extra properties, and empty required identities. Semantic checks enforce known/missing/value consistency and core-nutrient coverage meaning.

- [x] **Step 3: Add GoalVersion, DailyProgress, and DailyProgressResult**

`GoalVersion` has an exact six-key goal object, confirmation message, timezone, effective date range, and no population defaults. `DailyProgress.metric_order` is the exact six-item constant array. Totals/goals/increments/coverage all use exact six-key objects.

`DailyProgressResult` has:

```json
{
  "result_status": "committed",
  "result_kind": "write_finalized | direct_query",
  "daily_progress_by_date": ["one or more DailyProgress"],
  "daily_progress": "required only for exactly one date"
}
```

Semantic checks enforce nonnegative totals/goals/lower bounds, direct-query null increments, date sorting/uniqueness, one-date deep alias equality, and multi-date alias absence.

- [x] **Step 4: Add the full fixture templates and 42 cases**

Fixtures must include profile v1/v2, complete/partial/unknown snapshots, full/partial goals, single-day write, direct query, unknown fiber, water lower bound, and two-date signed correction. Invalid cases mutate one relevant property each and name the expected stable semantic fragment.
