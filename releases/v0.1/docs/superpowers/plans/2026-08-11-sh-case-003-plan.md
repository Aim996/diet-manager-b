# SH-CASE-003 Ops and Security Oracle Implementation Plan

> **For Codex:** Use the `executing-plans` skill to implement every task in order. Use `test-driven-development` for each behavior change and do not proceed past a failing verification without diagnosing it.

**Goal:** Extend the cumulative shared acceptance catalog with six deterministic privacy, zero-pollution, installation, migration-failure, immutable-candidate and export/restore safety Oracles, without implementing product operations.

**Architecture:** Keep one cumulative adapter-neutral JSON catalog. Add a separate `ops_security_scenarios` fixture collection, append six cases without changing the existing fourteen, and validate the new package with a focused PowerShell 5.1 validator plus real anti-weakening mutations. Existing core/domain validators continue to own only their previous subsets while accepting the registered cumulative suffix.

**Tech stack:** JSON, Windows PowerShell 5.1, Git, Markdown. No Node business runtime, database, installer, migration, deletion, network or OpenClaw execution.

**Design:** `docs/superpowers/specs/2026-08-11-sh-case-003-design.md`
