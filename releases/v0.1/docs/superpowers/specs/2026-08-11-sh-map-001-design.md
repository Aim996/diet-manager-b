# SH-MAP-001 Shared Model to B SQLite Mapping Design

## Goal

把 `SH-MODEL-001/002/003` 的冻结共享模型映射为一份可机器验证的 B SQLite v1 物理设计契约，同时保持 A 只读降级、C 不再独立建库，并把 C 的服务端预览、版本和状态守卫明确移交给未来 `B-MERGE-C-001`。

本任务只设计映射，不创建数据库、表、migration 程序、repository、worker 或业务数据。

## Chosen approach

采用一份 `shared/contracts/storage-mapping.md`，其中只有一个 `json storage-mapping/v1` 机器块。机器块同时冻结：

- B 唯一数据库文件名 `diet-manager-b.sqlite3` 和 `node:sqlite` 驱动；
- 四份上游 Schema 的 `$id`、SHA-256 和定义数量；
- 每个共享定义的存储模式以及全部字段的去向；
- 精确表、列名、SQLite affinity、可空性、默认值、主键、检查、外键和索引集合；
- `FactCommit`、`EffectBundle`、`EnvelopeFinalize` 和 migration 的写集合；
- fresh install、升级成功、升级失败和恢复矩阵；
- A/C 路线政策和 C 控制合并点；
- 技术日志与饮食业务数据库的物理、事务和查询隔离。

## Storage representation

### Extracted columns plus canonical JSON

身份、外键、状态、版本、日期时间和常用查询键使用显式 SQLite 列；每列固定 `name/type/not_null/default`，并由主键、唯一索引、外键和 `CHECK` 约束保护。嵌套对象、证据数组、可变候选集合和冻结响应使用 canonical JSON 文本列。

JSON 不是逃避字段覆盖：每个共享定义都必须把每个解析后的属性精确分配到 `columns`、`json`、`child_tables` 或 `response_only` 四组之一，组间不得重叠、不得遗漏。验证器只在四份上游 Schema 哈希精确匹配时解析字段，因此不能通过悄悄修改上游 Schema 来自适应假绿。

### Table ownership

- 事实与身份：`command_envelopes`、`idempotency_records`、`event_records`、`meal_items`、`products`、`inventory_batches`、`inventory_batch_projections`、`inventory_transactions`；
- 营养与进度：`nutrition_profiles`、`nutrition_snapshots`、`goal_versions`、`daily_progress_snapshots`；
- Issue/纠正/效果：`issues`、`issue_resolution_events`、`correction_events`、`effect_outbox`、`effect_bundle_commits`；
- 终态冻结：`envelope_finalizations`、`mixed_item_results`；
- 治理：`schema_migrations`。

## Transaction boundaries

### FactCommit

只允许写信封、幂等身份、事实事件/MealItem/CorrectionEvent 和初始 outbox。任一写点失败，业务事务全部回滚；允许在业务数据库外写脱敏技术日志，但饮食、库存、营养、Issue、outbox、进度、回执和终态幂等业务行均为零。

### EffectBundle

引用已提交事实，原子写营养快照、库存交易、Issue/解决事件、批次投影、效果提交记录和 outbox 状态。失败只回滚本效果包，不回滚事实，也不写最终回执或权威进度。

### EnvelopeFinalize

只在全部效果稳定终态后，原子写每日进度快照、终态冻结结果、mixed 子项和终态幂等结果。任一写点失败整层回滚，信封保持 `effects_pending`。

## Route policy

- B 是唯一写入路线；正式根由未来 B runtime 私有解析，不接受模型传入路径。
- A 只读/无插件降级，没有 SQLite writer、migration 或恢复器。
- C 不创建独立数据库；preview authority、data revision、transition guard、idempotency guard 和 migration guard 只登记为未来 `B-MERGE-C-001` 合并点。
- `shared/selected-route-map.json` 仍由未来 `X-GATE-002` 创建，本任务不得提前生成。

## Failure log policy

技术日志 sink 为独立、脱敏、非业务存储。它不得位于 `diet-manager-b.sqlite3`，不得参与业务查询，不得包含食品、数量、原始文本或可还原业务内容。技术日志成功或失败都不改变业务事务结果。

## Verification strategy

先写 PowerShell 5.1 validator 并固定上游 Schema 哈希、机器块 shape、34 个定义引用、20 张表、索引、事务/迁移/恢复/路线集合、物理契约摘要和 9 个 mutation。映射文件缺失必须先 RED；实现后必须在原工作区和 GitHub 独立 clone 复现，且业务数据库候选保持 0。

## Non-goals

- 不执行 SQL，不打开 SQLite；
- 不确定未来 repository 类名、内部函数或 worker 调度；
- 不实现 preview token、migration 或恢复逻辑；
- 不声称 G1/G2/G3、安装或产品可用。
