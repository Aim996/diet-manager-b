# B-STOR-002 Implementation Plan

**Goal:** Implement B-only atomic fact persistence, inventory effect/projection transactions and restart/idempotency recovery while proving that a failed write creates no dietary business row.

**Architecture:** Reuse B-STOR-001 SQLite/migration authority and B-MERGE-C-001 signed preview/state guards. `FactCommit` and `EffectBundle` are separate `BEGIN IMMEDIATE` transactions with deterministic replay markers. A redacted failure sink lives outside SQLite and is never a source of business truth.

**Tech stack:** TypeScript 5, Node.js 24 `node:sqlite`, Vitest.

## Constraints

- Follow `总功能开发计划0.3.md`; B remains the only product route.
- Do not implement the OpenClaw adapter, parser, nutrition, correction, progress or final receipt early.
- Do not change migration v1 unless a separately reviewed hard blocker proves the frozen mapping cannot express the repository.
- Do not read, hash, edit, track or execute the five protected paths.
- Tests use synthetic data in test-owned system-temp roots and never open official data.
- A failed `FactCommit` may write a redacted external diagnostic but must add zero business rows.
- Start every production behavior with a focused failing test.
- Use local deterministic tests for development; use one external model review only after candidate freeze.
