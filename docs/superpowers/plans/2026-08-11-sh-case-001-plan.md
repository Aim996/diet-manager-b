# SH-CASE-001 Core Acceptance Cases Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the legacy intent samples with five versioned, deterministic common acceptance cases for meal, single-item shape, plain water, receipt structure and current-day meal query behavior.

**Architecture:** `shared/acceptance-cases/cases.json` is the only case Oracle catalog, while `fixtures/core-v1.json` owns reusable deterministic setup data. An ASCII Windows PowerShell 5.1 validator carries independent literal expectations and mutations; future adapters consume the package but cannot rewrite it.

**Tech Stack:** JSON, Markdown, Windows PowerShell 5.1, existing CONTRACT-v2 and shared Schema files.

## Global Constraints

- Develop B only; A remains read-only degradation and C has no independent product implementation.
- Do not read, hash, edit, track or execute the five protected lease files.
- Do not create SQLite, DB, WAL, SHM, journal or JSONL business files.
- A failed FactCommit may create a separate redacted technical log but creates zero business artifacts.
- The five case IDs and all expected values are test-owned literals, never derived from the candidate JSON.
- Exact receipt prose and multi-day golden output remain outside this task.
- Every behavior change starts with a focused RED and ends with focused GREEN plus parser/data gates.
