# B-MERGE-C-001 Implementation Plan

**Goal:** Implement durable B-only server preview authority and pre-write guards without implementing a business repository or changing SQLite migration v1.

**Architecture:** Canonical JSON and HMAC-SHA256 freeze one exact preview binding. The existing SQLite control tables persist the binding and reserve idempotency under `BEGIN IMMEDIATE`. Read-only authorization compares token, stored authority, current request and data revision. Pure state/migration guards give B-STOR-002 deterministic preconditions.

**Tech stack:** TypeScript 5, Node.js 24 crypto and `node:sqlite`, Vitest.

## Constraints

- Follow `总功能开发计划0.3.md`; B is the only product route.
- Do not create or revive C product code, database, migration or plugin.
- Do not change migration v1 or the 20/18/22 mapping.
- Do not edit, read, hash, track or execute the five protected paths.
- Tests use only synthetic data in one test-owned temporary root; no official data root is opened.
- Preview success writes control metadata only. Every failure changes zero rows, and every dietary/business table remains empty.
- The Skill/OpenClaw tool remains non-writing until later tasks.
- Start each behavior with a focused failing test and observe the expected failure before implementation.
