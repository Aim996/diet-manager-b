## 1. 项目现在是什么

这是一个给智能体使用的饮食记录 Skill。Skill 负责理解用户意图和选择命令，B 后端负责权威数据、事务、幂等、库存、营养、纠正、查询和回执。OpenClaw、MCP 或其他智能体平台以后只接一层薄适配器，不复制业务规则。

当前仍是开发版本，不能用于真实饮食数据。已经完成 SQLite 基础和写入前服务端权威，但真正的饮食业务 repository、完整记录闭环、安装和部署还没有完成。

## 3. 已开发

### 3.1 必要安全与共同契约

- 必要 foundation 安全底座已按业务风险有界收口，不再追求无关平台细节的“完美化”。
- 共同业务契约、日期/回执、Issue/纠正契约已经冻结。
- 失败原子性规则已经固定：技术日志可以独立存在，但 `FactCommit` 失败时饮食记录、库存、营养、Issue、业务 outbox、进度和成功结果必须全部为零。
- 三组共同模型、确定性策略、B SQLite 映射、共同案例、共享 harness 和机器追踪已经完成。

### 3.2 B SQLite 基础（`B-STOR-001`）

- 使用 Node 24 内置 `node:sqlite`，不引入第三方 SQLite 驱动。
- 固定私有根和 `diet-manager-b.sqlite3` 文件名。
- migration 0001 精确建立 20 张表、18 个索引、22 个外键。
- 候选数据库先完整验证再发布，不覆盖已有数据库。
- 三个迁移故障点均证明：最终库、候选、WAL/SHM 无残留，可从零重试。
- 21 项包测试、TypeScript 和 OpenClaw 插件元数据门通过；独立复核 P0=0/P1=0。

### 3.3 B 服务端权威（`B-MERGE-C-001`）

- 服务端生成并保存 preview 权威，调用方状态不被信任。
- token 精确绑定 `preview_id`、版本、preview hash、输入 digest、主体范围、命令类型和数据 revision。
- canonical JSON 在读取值前拒绝动态 getter、自定义原型、稀疏数组、环和越界输入。
- 首次 preview 在一个 `BEGIN IMMEDIATE` 事务内写一条 envelope 和一条 idempotency；中途失败两条都回滚。
- 精确重试返回原 preview，行数不增加；同 key 改 digest、主体或命令稳定冲突且原记录不变。
- forged、ghost、stale、存储篡改、非法状态和非法 migration 全部在业务写前拒绝。
- schema 身份检查覆盖未登记的 table/index/view/trigger。
- 本地 27/27 focused、4 文件/48 测试、TypeScript、OpenClaw 插件门通过。
- OpenClaw 02 只做了一次有界独立审查，并额外验证并发锁、超时、篡改、schema 漂移和真实约束失败回滚；最终 P0=0/P1=0/P2=0，清理完成。

## 6. 发现问题与处理

| 问题 | 处理 |
|---|---|
| 只依赖调用方提交的 preview/state 会被伪造或陈旧状态绕过 | 改成 SQLite 中的服务端 authority + 签名 token；授权时重新读取并交叉核验 |
| 两张控制表分两次写可能留下半条记录 | 同一个 `BEGIN IMMEDIATE` 事务；故障注入已证明整体回滚 |
| 仅检查 table/index 会漏掉恶意 view/trigger | schema 身份枚举已覆盖全部非 SQLite 内建对象 |
| 测试 Oracle 曾把动态 preview hash 写成固定假值 | 已改为独立计算的真实 hash；产品实现无缺陷 |
| 外部审查的一个并发探针最初有自身同步竞态 | 审查员修正探针后重新运行，产品的锁串行化和唯一约束均通过 |

当前没有未关闭的 P0/P1/P2 发现项。

## 7. 当前正在开发：`B-STOR-002`

目标不是继续扩安全底座，而是开始真正的 B 原子 repository：

1. 在同一事务中调用已冻结的 preview authority。
2. 实现最小 `FactCommit` 数据写入和必要外键/非负约束。
3. 对同 key 并发、响应丢失、重启恢复和 WAL 行为做确定性验证。
4. 证明任何 `FactCommit` 失败都不会产生饮食记录、库存、营养、Issue、业务 outbox、进度或成功结果。
5. 技术日志若产生，必须是独立、脱敏、非业务的数据面，不能进入饮食查询。
6. 本任务完成后才能进入 B-only G1 硬安全门。
