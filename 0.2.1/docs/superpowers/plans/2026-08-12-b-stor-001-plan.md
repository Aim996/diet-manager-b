# B-STOR-001 Implementation Plan

**Goal:** Build the mapping-locked B SQLite bootstrap and initial migration without implementing business repositories or writing official data.

**Architecture:** A small internal storage module resolves one fixed database leaf beneath a trusted private root, initializes a candidate with built-in `node:sqlite`, applies one generated migration transaction, independently validates the result, and publishes only a fully valid candidate.

**Tech stack:** TypeScript 5, Node.js 24 `node:sqlite`, Vitest, OpenClaw package build/validate.

## Constraints

- B only; no A/C product implementation.
- Never read, hash, edit, track or execute the five protected paths.
- Tests write only under a unique test-owned temporary root; the formal B SQLite root stays read-only.
- No meal/water/inventory repository API, production business row or real user data in this task.
- A failure may be reported to a separate redacted diagnostic sink, but the business database must contain zero partial records.
- Start every behavior with a focused failing test.
