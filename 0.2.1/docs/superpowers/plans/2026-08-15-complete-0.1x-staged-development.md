# 饮食管家完整 0.1.x 分段实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 从冻结的 releases/v0.1 和当前 B 路线代码出发，补齐 v1.0 的 PRODUCT-0.1 全部范围，交付通过真实 OpenClaw、USDA 在线/离线、安装升级和灾备门禁的不可变 0.1.1。

**Architecture:** 保留现有 Parser → Application → Domain/FactCommit → Effect/Projection → Receipt 分层，只新增纠正目标解析、批量采购事务、便携加密备份和发布编排四个专责边界。releases/v0.1 永久只读，开发只发生在活动源码、shared 验收资产与 docs，最终只把通过真实环境验收的同一候选字节晋级到 releases/v0.1.1。

**Tech Stack:** Node.js 24、TypeScript、node:sqlite、Vitest、PowerShell 7、OpenClaw 2026.7.1、USDA FoodData Central、AES-256-GCM、scrypt、Git、SHA-256。

## Global Constraints

- 唯一需求权威是仓库根 饮食管家-开发约束与需求-v1.0.md；批准设计是 docs/superpowers/specs/2026-08-15-complete-0.1x-staged-development-design.md。
- 目标版本固定为 0.1.1；package.json、openclaw.plugin.json、发布目录、清单和 Git tag 必须一致。
- releases/v0.1 只读；任何测试、构建和验收都不得修改该目录。
- PRODUCT-0.2、健康建议、主动提醒、A/C 路线和通用研究平台均不进入本计划。
- 全局 WIP=1。任务必须按顺序完成；阶段出口未通过时不得开始下一阶段。
- 所有功能任务先写失败测试，确认失败原因，再写最小实现；禁止把测试改成适配错误行为。
- 所有写路径保留 I-1 至 I-8：事实优先、未发生不写、未知不等于零、库存非负且唯一匹配、原话保留、幂等、有界原子、可追溯。
- 不增加运行时依赖。Node 内置 crypto、fs、path、sqlite 足以完成加密备份和发布逻辑；若实施中确需依赖，先新增并批准 DEC，随后重开受影响任务。
- authority secret、FDC_API_KEY、Gateway 凭据、备份口令和真实饮食内容不得进入参数列表、普通环境清单、日志、Git 或发布包。
- Windows 测试前必须能导入 Microsoft.PowerShell.Security。环境不满足时返回 ENVIRONMENT_BLOCKED，不把连锁 secret/ACL 失败记为产品缺陷。
- 每个任务只提交列出的范围。提交前运行定向测试、邻接测试、TypeScript noEmit 和 git diff --check。
