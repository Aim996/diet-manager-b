# 饮食管家 0.2.1 整合修复总计划

- 整合时间：08-20-13.06（Asia/Shanghai）
- 整合范围：`0.2.1` 目录原有四份材料、01–05 真机结果、当前主线源码与 OpenClaw 2026.7.1 本地 SDK 类型
- 产品决策：基于现有主线渐进修改；不新建另一套技能，不推倒重写 SQLite 与事务内核
- 当前阶段：修复计划已合并，产品实现尚未开始；已有一份自然语言回归测试草稿，但尚未执行

## 一、统一结论

0.2.1 应先关闭用户链路中的四个 P0，而不是立即开展全面架构迁移：

1. 自然口语没有进入正确的专用 parser，回退成餐食解析；当模型请求 action 与 parser action 不一致时，被运行时包装为 `ACTION_CONFLICT`。
2. 模型可能完全不调用业务工具，却口头声称档案或目标已处理；也可能在工具结果之后追加初始化、内部维护内容或无依据建议。
3. 真实验收没有把必要 setup 的成功作为通过前提，导致前置写入全失败时仍能出现“查询通过”的假绿。
4. GitHub 自助安装混用了开发 link、临时目录、容器非持久数据根和跨平台测试，造成配置失效、数据丢失风险与会话超时。

现有 SQLite、事件追加、幂等、撤销/恢复语义、权威营养、备份恢复和冻结证据链保留。巨型模块拆分、依赖环清理和统一版本 manifest 属于后续结构债，不阻塞第一批 P0 修复。

## 二、证据状态表

| ToolPlugin 工厂能提供会话隔离键 | 已证实但有限 | `OpenClawPluginToolContext` 有 `sessionKey/sessionId`，但仍没有完整入站 message id 与 timestamp。若要宿主注入元数据，需改成 factory/hook 适配并继续验证来源。 |

## 三、去重后的问题清单

### P0-1：自然语言路由与有界语法

立即修复：

- 档案：支持“175高、65公斤”“身高是175、体重差不多65公斤”等日常连接词，仍要求必要字段与合理范围。
- 目标：支持“每天热量按 N 大卡”“喝水按 N 毫升”“蛋白质这一栏先不设/去掉”。
- 主体：有界支持“刚才、这会儿、我这会儿、是我自己/本人”，同时保留孩子、同事、家人等明确非本人反例。
- 撤销：支持“取消、去掉、前面那次算错了”等口语，仅在同一权威会话存在唯一 active 候选时自动绑定。
- 库存：支持“买回/带回来 + 明确商品与数量 + 放进库存”，缺商品或数量时继续澄清。
- 路由：专用意图必须在 meal fallback 前被接住；保持 `ACTION_CONFLICT` 守卫，并增加安全诊断 detail。

第一批不引入完整 `CommandRouter` 重构。先在现有 parser/route 结构上做有界修复并用真实原文锁定；等 P0 回归稳定后，再把统一路由边界作为结构阶段实施。

### P0-2：回复、工具结果与数据库一致性

- 工具未调用时，不允许验收为“已保存、已更新、已去掉”。
- `committed=false` 时，回复第一句必须明确本次未记录；不得追加身份初始化、内部维护命令、无依据营养建议或替代存储。
- 权威营养快照已经落库时，回复不得反称营养未匹配。
- 单靠 Skill 文案不足以提供强保证；短期在真实验收中加入“回复声明—工具调用—数据库增量”三方断言。
- OpenClaw 工作区初始化/人格内容是否能在插件层确定性抑制，当前 SDK 未提供直接的最终回复控制入口；先作为部署层复查项，不把它冒充成 parser 补丁。

### P0-3：消除真实验收假绿

- 每个必要 setup 明确期望 action、status/disposition、关键 DB 增量和必要 payload。
- 任一步失败即标记 `blocked_by_setup`，正式 input 不得计 PASS。
- 查询场景除零写入外，还要断言目标、当前值、百分比和进度条内容。
- 并行实例的脚本、备份、会话、证据和报告路径必须按实例隔离。
- 自然变体生成增加 dry-parse/route gate；发现语法缺口时保留失败，不把自然句自动改回规范句。

### P0-4：安装与持久化闭环

- 普通用户安装与开发 `--link` 分离；普通安装不得最终指向 `/tmp` 或 staging。
- 增加跨平台安装入口，候选包必须校验版本、大小和 SHA-256。
- 安装前确认程序根、数据根和备份根都位于持久挂载；容器 overlay 默认拒绝。
- 默认只跑 build/plugin validate/有界冒烟；完整测试显式开启并按平台分组。
- 安装需输出不含凭据的回执和回滚位置，并在删除下载目录、重启及重建容器后复核。
- 五号继续冻结现场；在迁移脚本和安装器回归通过前，不继续补丁式安装，也不迁移现有数据。

### P1：权威元数据与多轮澄清状态

本项已经明确不能直接在当前 static `execute` 回调里完成：

- `execute` 只有稳定 `toolCallId`，没有入站 message id、timestamp 或 session key。
- factory 上下文可取 `sessionKey/sessionId`，可用于会话隔离，但不足以生成完整权威审计元数据。
- 后续需要验证 factory + host hook/run context 的组合，或由插件维护绑定会话的 pending candidate；不能继续要求模型虚构缺失字段。
- pending candidate 必须有过期时间、绑定 action/conversation/source，跨会话、多候选或过期继续拒绝。

### P1：工程治理与结构债

- 拆分 portable、Windows-only、integration、real-acceptance 测试和 CI 结果。
- 统一版本、契约、候选与平台信息的机器权威 manifest。
- 在行为修复稳定后拆 `core-runtime.ts`、`effect-bundle.ts`、`domain/service.ts`，并用 ports 清除已发现的依赖环。
- 该阶段不得与数据库 schema 迁移或新的业务功能混在同一批改动中。

## 五、完成标准

- 真实自然原话进入正确的确定性 action；明确他人主体仍保持零写入。
- 目标设置/清除、饮水、库存、撤销/恢复不再因 meal fallback 产生伪冲突。
- 工具未调用或 `committed=false` 时，用户回复不得声称成功。
- setup 失败绝不显示 PASS；进度查询返回值与数据库一致。
- 同消息重放保持幂等，不同消息不复用操作或来源标识。
- Linux portable 测试无真实失败；Windows-only 门禁在 Windows 单独验证。
- 普通安装不依赖临时 link；容器删除重建后插件、数据库和 authority secret 仍在持久卷。
- 01–04 业务回归和 05 干净安装回归全部完成后，才允许发布 0.2.1。

## 六、仍需复查但不阻塞批次 A/B 的事项

1. OpenClaw 是否有稳定、公开的 hook 能把入站 message id 与 timestamp 安全绑定到 tool factory；当前 `ToolPluginExecutionContext` 明确不提供。
2. 最终助手回复能否通过公开插件 API 做确定性校验/改写；当前只证实 Skill 与工具描述属于软约束，不能单独保证。
3. 多轮确认最终采用 SDK 受信上下文还是插件自有 pending state；在找到完整权威元数据前，不把模型拼接历史当作可信来源。
4. 五号数据迁移的具体执行窗口与回滚演练；在迁移器通过隔离测试前保持现场不动。
