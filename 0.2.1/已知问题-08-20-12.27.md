# 饮食管家 0.2.1 已知问题

- 首次记录时间：08-20-12.27（Asia/Shanghai）
- 来源版本：0.2.0 candidate-010
- 验证环境：OpenClaw 01–05 真机实例
- 记录原则：区分“多实例已复现”“单实例已发现”“待四号复现”，避免把推测写成结论。

## P0：自然语言目标操作频繁失败

状态：01、02、03 多实例已复现；04 待独立复现。

- 用户已经明确给出热量目标，系统仍返回冲突或继续要求澄清。
- 用户按回复建议补充或改用更明确的说法后，仍可能无法写入。
- 影响：日常表达下核心目标无法建立，数据库保持零写入。

## P0：验收场景存在“假绿”

状态：01、02、03 多实例已复现；04 待独立复现。

- 进度查询场景只检查查询阶段没有新增写入，没有验证前置目标和饮水记录是否成功落库。
- 当前置数据全部写入失败时，查询仍可能被脚本判定为通过。
- 影响：测试报告可能显示通过，但用户实际看到的是空数据或错误目标。

## P1：清除营养目标无法稳定完成

状态：01、02、03 多实例已复现；04 待独立复现。

- “蛋白质先不设了”“帮我去掉蛋白质目标”等自然表达可能被判冲突、信息不完整或无需修改。
- 即使继续确认，目标仍可能不落库。
- 影响：用户无法可靠撤销单项营养目标。

## P1：回复夹带无关初始化或错误状态声明

状态：01、02、03 已发现不同表现；04 待独立复现。

- 业务操作完成后，回复可能追加助手身份、名称或性格初始化内容。
- 个别失败流程中，回复曾声称档案已经更新，但数据库没有对应写入。
- 个别回复还暴露了与饮食业务无关的内部维护内容。
- 影响：回复不可信、干扰正常对话，并可能误导用户认为操作已成功。

## P1：冲突与澄清逻辑重复索取已提供信息

状态：02、03 已复现，01 有同类表现；04 待独立复现。

- 用户已经给出单位、目标值或覆盖意图，系统仍反复要求提供相同信息。
- 部分提示要求用户同时表达互相矛盾的操作意图。
- 影响：对话无法自然推进，用户按提示操作也难以完成任务。

## P1：GitHub 自助安装路径不可靠

状态：05 单实例已发现；独立根因复核已于 08-20-12.38 完成。

- 直接读取 GitHub 页面可能被运行环境的网络策略阻止。
- 自动安装流程误用了面向开发的临时链接安装，临时目录消失后导致配置失效。
- 虽然后续自行恢复为稳定插件路径，但数据目录选在容器非持久化位置，容器重建后存在丢失风险。
- 完整测试还包含依赖 Windows 环境的用例，Linux 容器中出现环境性失败。
- 影响：普通用户可能看到超时、配置损坏或重建后数据丢失。
- 详细证据与文件级计划：`0.2.1/五号GitHub自助安装根因与修复计划.md`。

## P2：安装流程需要人工补齐配置与初始化

状态：04 的 SSH 安装已验证。

- 插件包安装后，必须另行配置官方数据根并初始化目录，才能通过配置校验并正常启用。
- 影响：安装文档若未明确编排这两个步骤，用户容易把正常的保护性失败误认为安装损坏。

## 测试基础设施问题

状态：已定位并在本轮测试中规避。

- 并行实例最初共用了远端临时脚本路径，存在相互覆盖风险。
- 当前 01、02、03 已改用实例专属临时文件和证据目录，未发现数据损失。
- 后续修复要求：执行器必须按实例隔离脚本、会话、数据库备份和报告路径。

## 四号独立复现结果

- 复现时间：08-20-12.37（Asia/Shanghai）
- 环境：04 安装后数据已移入可恢复备份；在独立空库、独立会话中复现。

### 已确认的同类用户影响

1. 首次档案消息没有调用饮食管家工具，回复被身份初始化和未经工具支持的饮食建议占据；`user_profiles` 与 `goal_versions` 均为 0。
2. 自然表达设置 1800 大卡时没有调用饮食管家工具，但回复把它说成已经定下的计划；数据库目标仍为 0。
3. 自然表达清除蛋白质时没有调用饮食管家工具，回复声称已经去掉，并继续声称计划剩下 1800 大卡；数据库中两项都不存在。
4. 自然表达设置 1000ml 饮水目标时，回复明确说只作口头计划、不正式记录；目标数据库仍为 0。
5. 500ml 白水记录随后成功调用工具并落库；查询能读出 500ml，同时说明没有正式饮水目标。

### 与二号的差异

- 04 没有复现完全相同的 `ACTION_CONFLICT` 返回；它在档案、热量和清除蛋白三步中直接绕过了业务工具。
- 两者最终用户影响相同：核心目标零写入；但 04 还出现了更强的回复误导——把未落库状态描述成已经处理。
- 因此当前应分别记录为“工具动作与解析动作冲突”和“模型未调用业务工具/回复越权”，不能合并成单一根因。
