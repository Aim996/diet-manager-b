# B SQLite Storage Mapping v1

本文档是共享领域模型到未来 B 路线 SQLite 存储的唯一映射契约。它不是迁移脚本，也不会创建数据库。所有嵌套或可变结构写入 `payload_json` 时，必须使用 UTF-8、对象键 Ordinal 排序、无多余空白的 canonical JSON；读取后仍须通过对应共享 Schema 与语义不变量。

## 写入分层

- `fact_commit`：只提交命令信封、幂等身份、不可变事实、餐食子项、纠正事实和初始 outbox。任何失败整层回滚；可在数据库外写脱敏技术日志，但业务表零新增。
- `effect_bundle`：只基于已提交事实写营养、库存、Issue、投影、效果状态，并把命令信封从 `effects_pending` 推进到 `effects_stable`；失败不回滚事实，也不产生最终回执。
- `envelope_finalize`：只在效果稳定后原子冻结每日进度、回执、mixed 子项和终态幂等结果；失败时信封保持 `effects_pending`。

## 实现约束

未来 migration 必须从机器块机械生成或逐项对照，不能自行改名、放宽可空性或跳过约束。`payload_json` 只保存对应 `field_groups.json` 的字段；它不是整对象的第二份副本。response-only 定义只存在于命令响应或冻结终态 payload 中，不单独创建业务表。

技术日志只允许记录稳定错误码、阶段、关联追踪 ID 和不可逆摘要；禁止写食品名称、数量、原话、完整 Schema 对象或 SQLite 页面。日志写入失败也不得反向改变业务事务的提交/回滚结果。
